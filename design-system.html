Rearchitecting a design system for energy management apps

Rehlko's Home Energy apps let dealers, technicians and homeowners monitor and control generators and transfer switches. The design files behind them had become slow, cluttered and hard to search. I restructured the whole Figma ecosystem so designers can find what they need and start new work in minutes.

Context

The problem

When I joined, each app had one Figma file holding everything: components, projects, discovery, archives and stray pages from several designers.

  • Scale. Files slowed down and glitched as pages piled up, and every new project raised the risk of errors.
  • Findability. Inconsistent names and projects nested inside pages made past work hard to search and reuse.
  • Efficiency. Incomplete components meant designers rebuilt screens from scratch, which also slowed onboarding.

Process

How I got buy-in

  1. Prototyped the structure. I built a demo Figma space showing a cleaner organization model.
  2. Pitched it. I walked the lead designer through the model before changing anything.
  3. Migrated. I moved every file to its designated location.
  4. Audited. I reviewed global and local components to find gaps and plan what to build next.

Solution

The new structure

A global components file that contains only shared components.

A folder for each app with a local component file for product-specific components and screens, plus a pinned project template.

Project templates with libraries preloaded. A designer duplicates the template, adds the Jira ticket number and starts designing.

The result is more efficient designers, less duplicate work, better consistency and faster onboarding.
